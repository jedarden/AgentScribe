# projects.rs Module Investigation

**Bead-Id:** bf-6175

## Summary
The `src/projects.rs` module (708 lines) is currently unused - no call sites outside of its own tests.

## What the module does
Implements a project registry system using `projects.yaml`:

- **Schema support**: v0.1 (shorthand `path:`) and v0.2 (explicit `workspaces:` list)
- **Project metadata**: name, optional label, optional hex color
- **Workspaces**: Multiple paths per project with role labels (e.g., "primary", "manifests", "secrets")
- **Operations**: load, validate, save, migrate (v0.1→v0.2)
- **Testing**: 37 comprehensive unit tests covering validation, warnings, migration, round-trip

## Why it's unused
- Not wired into any CLI commands
- Not imported by any other source module
- Only referenced in its own test code
- No existing `projects.yaml` files in codebase

## Design intent (inferred)
The module appears designed for project-aware operations:

1. **Project-scoped search**: Search all sessions for "my-webapp" regardless of workspace path
2. **Multi-repository projects**: Track related repos under a single project name
3. **Project grouping**: Analytics, reporting, or rules scoped by project rather than path
4. **Workspace roles**: Distinguish primary code from manifests, secrets, etc.

## Decision: Document as future feature

**Leave the module in place** and document it here. The implementation is well-designed and could be valuable for:

- Enhanced search: `agentscribe search --project ibkr-mcp` (looks up all workspace paths)
- Project analytics: Cross-workspace statistics
- Rules extraction: Generate rules for all workspaces under a project
- Project metadata reporting: Colors and labels for UI/display

### Potential integration paths

1. **CLI command**: `agentscribe projects` subcommand for listing/managing registry
2. **Config path**: `~/.agentscribe/projects.yaml` as canonical location
3. **Search integration**: Resolve `--project` flag against registry
4. **Analytics integration**: Group sessions by project name
